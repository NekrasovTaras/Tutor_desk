# TutorDesk

**Рабочее пространство репетитора: ученики, расписание и домашние задания.**

Первая версия Python-проекта для совместной разработки и портфолио. FastAPI обслуживает JSON API и готовый адаптивный интерфейс на русском языке. Данные сохраняются в БД и остаются после перезапуска.

## Что работает в 0.1

- Регистрация репетитора, вход, выход и смена пароля.
- Карточки учеников: предмет, класс, цель, контакт, личные заметки, архивирование и восстановление.
- Создание отдельного аккаунта ученика при добавлении карточки.
- Недельное расписание: добавление и перенос занятий, длительность, стоимость, статусы «запланировано / проведено / отменено».
- Запрет пересечения занятий одного репетитора, включая одновременные запросы.
- Домашние задания со сроком сдачи и необязательной привязкой к занятию.
- Ученик отправляет текстовый ответ; репетитор оставляет комментарий и оценку от 0 до 100.
- Обзор ближайших занятий, заданий на проверке и результатов учеников.
- SQLite по умолчанию, конфигурация PostgreSQL через Docker Compose.
- Миграции Alembic, документация API, интеграционные тесты и GitHub Actions.

## Быстрый запуск в PyCharm на Windows

Рекомендуемая версия — **Python 3.12**. Именно на ней выполнены проверки проекта.

1. Распакуйте архив. Откройте в PyCharm **папку `tutordesk`**, внутри которой лежат `run.py` и `requirements.txt`: **File → Open**.
2. Если вы уже создали пустой проект, скопируйте в него **содержимое** папки `tutordesk`. Не заменяйте свою `.venv`: её в архиве нет.
3. В **Settings → Project → Python Interpreter** выберите Python 3.12 и создайте виртуальное окружение `.venv` для этого проекта. Названия пунктов могут немного отличаться между версиями PyCharm.
4. Откройте нижнюю вкладку **Terminal**. Убедитесь, что терминал находится в папке с `run.py`, и выполните:

```powershell
python -m pip install -r requirements.txt
python -m app.seed
python run.py
```

5. Откройте **http://127.0.0.1:8000** в браузере. Пока приложение нужно, терминал с сервером должен оставаться запущенным. Остановка — `Ctrl+C`.

В дальнейшем можно запускать `run.py` зелёной кнопкой **Run** в PyCharm. Проверьте, что выбран интерпретатор именно этого проекта. При изменении Python-кода сервер автоматически перезапускается.

**Команда `python -m app.seed` необязательна.** Она добавляет вымышленные данные для знакомства с интерфейсом. Для чистого рабочего кабинета пропустите её и зарегистрируйте свой аккаунт. Повторный вызов seed не стирает существующие данные и не создаёт вторую копию демо.

### Демо-аккаунты

Они доступны только после запуска `python -m app.seed`.

| Роль | Email | Пароль |
| --- | --- | --- |
| Репетитор | `teacher@tutordesk.local` | `TutorDemo123!` |
| Ученица Аня | `anna@tutordesk.local` | `Student123!` |

Демо-пароли опубликованы в исходниках и предназначены для локального знакомства. Для собственных данных зарегистрируйте новый аккаунт. Скрипт создаёт всего четырёх вымышленных учеников и занятия относительно даты запуска.

### Если Python или окружение ещё не настроены

Из папки проекта в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m app.seed
.\.venv\Scripts\python.exe run.py
```

Активация окружения не нужна, поэтому запрет PowerShell на запуск `Activate.ps1` не мешает. Если команда `py` не найдена, сначала установите Python 3.12 с официального сайта https://www.python.org/downloads/ и заново откройте терминал.

Для macOS/Linux:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m app.seed
.venv/bin/python run.py
```

## Как попробовать приложение

1. Войдите под репетитором и откройте «Ученики».
2. Добавьте ученика: укажите имя, email и начальный пароль. Доступ создаётся сразу; отправки писем нет. Передайте данные ученику самостоятельно.
3. В расписании выберите день, нажмите «Новое занятие», задайте тему и время.
4. Попробуйте создать второе занятие с пересечением: приложение покажет понятную ошибку.
5. Выдайте ДЗ ученику. При желании выберите связанное занятие этого ученика.
6. Выйдите, войдите под учеником, откройте задание и отправьте решение.
7. Снова войдите под репетитором, проверьте ответ и поставьте оценку.

Можно открыть кабинет ученика в приватном окне браузера, чтобы одновременно работать с двумя ролями. В обычных вкладках одного браузерного профиля используется общий аккаунт.

### Несколько важных правил приложения

- Все даты интерфейса — **Москва, UTC+3**, независимо от часового пояса компьютера. API принимает ISO 8601 с часовым поясом; внутри БД время хранится в UTC.
- Ученик видит свои занятия и ДЗ. Контакт и личные заметки преподавателя не включаются в ответы API ученику.
- Каждый аккаунт ученика привязан к одному преподавателю; email уникален во всём приложении.
- Отменённое занятие освобождает время. Проведённое занятие сохраняет своё место в истории расписания.
- Архивирование ученика сохраняет историю, доступ в кабинет и ранее назначенные занятия. Новые занятия и ДЗ для архивного ученика запрещены; при необходимости отмените оставшиеся занятия отдельно.
- Связанное с ДЗ занятие нельзя переназначить другому ученику.
- Ученик может исправлять ответ до проверки. После проверки ответ фиксируется, преподаватель может поправить оценку и комментарий.
- Сумма в обзоре — стоимость проведённых занятий за текущий месяц. Это **не подтверждённые оплаты**: платёжного модуля здесь пока нет.
- «Результат ДЗ» — средняя оценка проверенных заданий; это не прогноз балла ЕГЭ.

| `app/services.py` | Права на записи, сериализация, проверка расписания |

Запрос из браузера проходит через API → проверку сессии и прав → бизнес-логику → SQLAlchemy → БД. В интерфейсе нет отдельного хранилища учебных данных: после обновления страницы они загружаются с сервера.

Это один Python-сервис с разделением по ответственности. В первой версии синхронный SQLAlchemy используется внутри обычных `def`-обработчиков FastAPI, которые выполняются в пуле потоков.

### Почему нельзя забронировать одно время дважды

Простой проверки `SELECT` перед `INSERT` недостаточно: два запроса могут одновременно увидеть свободное время.

- В SQLite изменяющий запрос начинает `BEGIN IMMEDIATE` **до чтения**. Другой изменяющий запрос ждёт завершения транзакции, затем читает актуальные данные. Для небольшой локальной нагрузки это понятный компромисс: записи сериализуются на уровне всей БД.
- В PostgreSQL изменение расписания блокирует строку преподавателя через `SELECT ... FOR UPDATE`. Проверка пересечения и сохранение занятия выполняются в одной транзакции. Репетиторы с разными строками не блокируют расписания друг друга.
- Интервалы полуоткрытые: урок 15:00–16:00 и урок 16:00–17:00 разрешены.

Все записи расписания должны проходить через этот сервис; произвольная запись в БД обходным SQL не защищается проверкой сервиса. Проверки конкурентного бронирования выполнены на SQLite; PostgreSQL-ветка требует отдельного прогона.

### Авторизация

Пароли хранятся как PBKDF2-HMAC-SHA256 с индивидуальной случайной солью. В браузере — случайный идентификатор сессии в `HttpOnly`, `SameSite=Strict` cookie. В БД хранится SHA-256-хеш этого идентификатора. Сессия действует 7 дней.

Изменяющие запросы требуют `X-CSRF-Token`; при наличии `Origin` он должен совпадать с адресом приложения. Смена пароля отзывает все сессии пользователя. Для регистрации и входа есть простой лимитер одного процесса: 30 запросов за 10 минут на IP.

## API

После запуска: **http://127.0.0.1:8000/docs**. Swagger UI загружает свои ресурсы из CDN, поэтому для его отображения нужен интернет. Основной интерфейс использует только локальные файлы.

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/api/auth/register` | Создать аккаунт преподавателя |
| POST | `/api/auth/login` | Войти и получить cookie |
| GET | `/api/auth/me` | Текущий пользователь и CSRF-токен |
| POST | `/api/auth/logout` | Выйти |
| POST | `/api/auth/password` | Сменить пароль и отозвать сессии |
| GET, POST | `/api/students` | Список / создание ученика |
| PUT | `/api/students/{id}` | Изменить карточку или архивировать |
| GET, POST | `/api/lessons` | Список / создание занятия |
| PUT | `/api/lessons/{id}` | Изменить, перенести или отменить занятие |
| GET, POST | `/api/homework` | Список / создание задания |
| POST | `/api/homework/{id}/submit` | Ответ ученика |
| POST | `/api/homework/{id}/review` | Проверка преподавателем |
| GET | `/health` | Проверка работы приложения |

Пример из Python (сервер должен быть запущен):

```python
import httpx

with httpx.Client(base_url="http://127.0.0.1:8000") as client:
    response = client.post("/api/auth/login", json={
        "email": "teacher@tutordesk.local",
        "password": "TutorDemo123!",
    })
    response.raise_for_status()
    client.headers["X-CSRF-Token"] = response.json()["csrf_token"]
    print(client.get("/api/students").json())
```

Для ручной отправки изменяющих запросов через Swagger войдите в том же браузере, выполните `GET /api/auth/me`, скопируйте `csrf_token` и вставьте его в поле `X-CSRF-Token` нужного запроса. Для чтения достаточно сессии в том же браузере.

## Тесты и миграции

```bash
python -m pytest
python -m alembic current
python -m alembic check
```

Тесты используют отдельные временные БД и не трогают данные вашего кабинета. Проверяются права преподавателей и учеников, сессии, CSRF, отзыв сессий, сохранение данных после перезапуска, пересечения и переносы занятий, конкурентное бронирование, архивирование, привязка ДЗ и полный цикл проверки задания.

Миграции автоматически применяются при локальном запуске одного процесса. После будущего изменения моделей:

```bash
python -m alembic revision --autogenerate -m "describe_change"
python -m alembic upgrade head
```

Перед применением прочитайте сгенерированную миграцию и сохраните резервную копию БД. Для нескольких серверных процессов миграции нужно вынести в отдельный этап перед запуском приложения.

## PostgreSQL через Docker — необязательный следующий шаг

При установленном Docker с Compose:

```bash
docker compose up --build
```

В другом терминале, если нужны демо-данные:

```bash
docker compose exec app python -m app.seed
```

Адрес приложения остаётся **http://127.0.0.1:8000**. `docker compose down` останавливает контейнеры, сохраняя данные в named volume. Не добавляйте `-v`, если хотите сохранить базу.

Для работы Python из PyCharm с PostgreSQL в контейнере запустите только БД: `docker compose up -d db`. Скопируйте `.env.example` в `.env` и включите строку `DATABASE_URL` с `localhost:5432`, затем запустите `run.py`.

SQLite и PostgreSQL — независимые базы. Переключение подключения не переносит существующие записи. Compose содержит только локальные демонстрационные реквизиты и открывает порты на `127.0.0.1`.

## Границы версии и следующий этап

Первая версия предназначена для локальной разработки. В ней пока нет восстановления пароля по почте, уведомлений, вложений, повторяющихся занятий, оплат, пагинации и автоматического обновления открытого кабинета. Для получения изменений из другой вкладки обновите страницу.

Перед публичным размещением нужны отдельная настройка HTTPS/`COOKIE_SECURE=true`, управление регистрацией и демо-аккаунтами, резервные копии, общий лимитер для нескольких workers, журналы действий и тестирование PostgreSQL. Сроки и ресурсы публикации в эту поставку не входят.

Первый совместный учебный этап: запустить приложение, пройти сценарий с двумя ролями и разобрать один запрос целиком — например, создание ученика. Затем добавить редактирование ДЗ и написать для него тесты.

## Если что-то не запускается

| Симптом | Что проверить |
| --- | --- |
| `ModuleNotFoundError` | Установлены ли зависимости в интерпретатор, выбранный в PyCharm? Используйте `python -m pip`, а не отдельный `pip`. |
| `No module named app` | Терминал и Working directory должны указывать на папку с `run.py`. |
| Демо-вход не работает | Запустите `python -m app.seed` с тем же `.env` и тем же подключением к БД. |
| Порт 8000 занят | Остановите старый сервер или выполните `python -m uvicorn app.main:app --reload --port 8001` и откройте порт 8001. |
| Вход успешен, но аккаунт не сохраняется | Для обычного `http://localhost` / `http://127.0.0.1` оставьте `COOKIE_SECURE=false`. |
| Не удаётся подключиться к PostgreSQL | Проверьте Docker, порт 5432 и `DATABASE_URL`. Для первого знакомства можно вернуться к SQLite. |
